# Установка единственной актуальной копии KinoPub

Репозиторий: https://github.com/aomikh/lampa_kinopub, ветка `main`, опубликованный файл `docs/kp.js`. Редакция **1.0.73-mx.9** исправляет передачу нативным и внешним плеерам Apple TV: убраны лишняя загрузка медиассылки для журнала, подмена выбранного URL общим качеством ядра и отметка просмотра при передаче ссылки. Кнопка «Смотреть» сразу открывает KinoPub, как в mx.8. Быстрый запуск встроенных tvOS Pro / Universal / Online подтверждён сообщением пользователя до правки; скорость новой редакции и устранение ошибки Infuse на устройстве не проверены.

Постоянный адрес: https://aomikh.github.io/lampa_kinopub/kp.js

Адрес обновления: https://aomikh.github.io/lampa_kinopub/kp.js?v=1.0.73-mx.9. Параметр `v` обходит кэш, но не закрепляет содержимое. Старые значения `v` не возвращают старую версию.

## Действия на Apple TV

1. Lampa MX → Настройки → Расширения: замените адрес существующего KinoPub на адрес обновления. Оставьте один активный KinoPub; не добавляйте вторую копию.
2. Полностью закройте Lampa MX и откройте вновь. Сохраните уже работающий **Встроенный tvOS Online**, Universal или Pro в настройке плеера. Для сравнения меняйте только плеер. Формат KinoPub «Авто» использует HLS2, поток по HTTP из отдельных сегментов. На карточке нажмите **Смотреть**: должен сразу открыться KinoPub без меню источников и отдельного значка.
3. Для максимального разрешения проверьте существующую настройку KinoPub «Макс. качество»: значение 1080 ограничивает выбор до 1080p, даже если есть 2160p. Для 4K нужен предел 2160. Это общая настройка плагина, затрагивающая и другие плееры; код её автоматически не меняет. Повышение предела не исправляет Range и не гарантирует поддержку конкретного HDR/кодека устройством.
4. Запустите один и тот же фильм через выбранный встроенный режим. Проверьте первые несколько минут, затем перемотку, дорожки, субтитры, возврат и продолжение. Отдельно проверьте серию первого сезона «Восьмидесятых». Не меняйте одновременно маршрут, регион, кэш и качество. Зафиксируйте время до первого кадра; быстрый старт не доказывает устойчивость всего фильма.
5. Для отдельной проверки Infuse выберите именно Infuse. Если ошибка повторится, вернитесь в ту же сессию Lampa MX, не запуская другой материал, и откройте **Настройки → KinoPub → Диагностика Infuse**. В заголовке должна быть mx.9. Подождите до 30 секунд, снимите сводку и подробности неуспешного запроса. Эта диагностика относится только к последней попытке Infuse, не к встроенным tvOS-плеерам.

Новый снимок mx.6 уже получен: подготовка 387 мс, передача 1 мс, начало ответило 206, середина и конец не ответили за 6 секунд из Lampa. Для продолжения нужны точная версия Infuse и запись именно проблемного видеопотока Infuse в журнале Shadowrocket: время, домен без пути, сработавшее правило, DIRECT/PROXY, объём и ошибка. Настройки маршрутов пока не менять. Диагностические запросы Lampa не путать с потоком Infuse. Подписанные URL, токены, пароли и данные подписки присылать не нужно.

## Что изменилось

В mx.9 сохранены штатные схемы запуска всех плееров Apple TV. Для делегированного воспроизведения отключены лишний GET медиассылки, внутренняя цепочка повторных запусков и отложенный вызов переключения аудио в веб-плеере. Объект качества не позволяет ядру заменить уже выбранную ссылку. Позиция не сбрасывается, данные дорожек/субтитров/плейлиста сохраняются; фактическая поддержка этих полей зависит от адаптера и оболочки. Сам факт передачи не отмечает фильм просмотренным. Ошибка синхронной передачи показывает KP-A1 без автоматических повторов. Ошибки внутри уже открывшегося приложения этим кодом не перехватываются.

У Infuse путь остаётся прежним, с прямым файлом и документированной позицией. Встроенные режимы при «Авто» продолжают получать HLS2. Точные параметры их буфера и декодеров нельзя установить из JavaScript-ядра. [Разбор каждого плеера](audit/apple-players-review-20261004.md).

В mx.8 исправлено неверное толкование пожелания пользователя в mx.7. Отдельный значок KinoPub убран. Обычная кнопка «Смотреть» открывает `online_kp` напрямую для текущей карточки. Ядро Lampa заново назначает обработчик при возврате на карточку; плагин учитывает это событие и сохраняет прямой вход. Дополнительная закреплённая кнопка KinoPub не создаётся. Другие закреплённые источники и настройки не удаляются, Tizen сохраняет прежнее меню. На старой раскладке без кнопки «Смотреть» остаётся прежний вход в источник.

Отметка качества строки могла быть вычислена для HLS другого плеера либо только для вариантов, уже имеющих URL. Она ошибочно ограничивала Infuse до 1080p при доступном файловом варианте 2160p и разрешённом пределе 2160. Теперь обычный запуск Infuse выбирает максимум среди реальных прямых файлов в заданном пределе. Явный выбор качества остаётся точным. Разрешение само по себе не доказывает битрейт, кодек, HDR или совместимость.

Фильм с известным `files[].file` по-прежнему получает одну свежую ссылку через `/items/media-video-link?file=…&type=http`. Перед запуском нет HEAD/GET, ожидания health, подмены CDN или manifest-proxy. Подпись и HTTPS сохраняются; позиция не обнуляется. Дорожки остаются в исходном файле, внешний интерфейс передаёт один URL субтитров на видео. Выбор аудиодорожки выполняется в Infuse.

Документированный интерфейс Firecore указан для **Infuse 8.4.7+**: https://support.firecore.com/hc/en-us/articles/215090997-API-for-Third-Party-Apps-Services. Версия установленного клиента неизвестна. Открытие Infuse не означает успешного воспроизведения; подтверждённой схемы возврата/синхронизации прогресса для установленной Lampa MX нет.

## Что проверяет диагностика

До пяти запросов, каждый до шести секунд, без повторов:

- HEAD;
- GET `bytes=0-1023`;
- 1024 байта с середины текущего файла, если известен размер;
- GET от той же середины до конца;
- последние 1024 байта.

Смещение 205444144 из старого снимка не применяется к произвольному фильму. Если размер недоступен, середина не выдумывается. Ответы 200 вместо диапазона, неправильный Content-Range, отказ 416 и изменение размера показываются отдельно. Один код 206 не считается достаточным результатом.

**В Lampa проверяются только заголовки, тело не читается.** Ответ прерывается сразу, включая 200 и открытый диапазон. Сетевой стек может успеть принять данные до отмены; нулевые байты означают нулевое чтение приложением, не измерение трафика. Отсутствующий заголовок может быть скрыт CORS. Браузер раскрывает конечный узел и факт перенаправления, но не всю цепочку и не заголовки каждого перехода.

Подготовка ссылки и интервал «готовая ссылка → передача Infuse» измеряются отдельно. Время до первого кадра, перемотки и реальная скорость внутри Infuse автоматически не измеряются. Свежесть ссылки при запуске не гарантирует её пригодность спустя время. После истечения или отказа нужна новая обычная попытка; плагин не перезапускает видео автоматически.

## Ограниченная проверка тела вне Apple TV

`tools/probe_media.py` читает одну разрешённую свежую ссылку из stdin. POSIX, Python 3, без дополнительных зависимостей:

```sh
python3 tools/probe_media.py < /private/current-link.txt
```

Только для **того же файла**, на котором получена соответствующая ошибка:

```sh
python3 tools/probe_media.py --offset 205444144 < /private/current-link.txt
```

URL не помещать в командную строку или репозиторий. Лимит — 20 секунд на весь запуск, до пяти запросов, до трёх перенаправлений на запрос и до 1024 прочитанных байтов каждого корректного 206 (до 4096 всего). Ответ 200, неправильный диапазон, авторизация и кодирование содержимого не читаются. Для отдельной проверки реально наблюдавшегося If-Range предусмотрен `--if-range`: ещё один ограниченный запрос, всего до 5120 байтов, в тех же 20 секундах. Результат не доказывает маршрут/скорость Infuse на Apple TV.

## Контроль и откат

Проверить: один фильм максимального доступного совместимого качества; одну серию первого сезона «Восьмидесятых» и её изображение; материал с несколькими дорожками и субтитрами; перемотку вперёд/назад, возобновление и возврат в Lampa MX. Проверка нескольких минут не доказывает отсутствие обрыва всего фильма.

Для отката mx.9 восстановите только `docs/kp.js` из `71b15e3900f4c489992ef5b0d28efb71b8105206` командой `git restore --source=71b15e3900f4c489992ef5b0d28efb71b8105206 -- docs/kp.js`, создайте обычный новый коммит в `main`, обновите сведения выпуска и опубликуйте. Это вернёт mx.8, сохранив прямую кнопку «Смотреть». Историю не переписывать, старые исполняемые копии в `docs` не создавать. После публикации обновите кэш единственного URL. Авторизацию и настройки Shadowrocket не очищать.
