# Lampa MX / KinoPub: проверка путей и исправления mx.11

Проверено 04.10.2026. Репозиторий изменений: только `aomikh/lampa_kinopub`, основная ветка `main`, публикуемый файл `docs/kp.js`. Исходники автора не изменялись. Ревизия ядра для анализа: `yumata/lampa-source@b4a13b6af7fe2f3bbbcb91f4eb434ab3378f8d5d`; проверка удалённой main подтвердила ту же ревизию. Номер ядра 335 не является версией нативной Lampa MX. Версия установленной оболочки и tvOS неизвестна. Infuse 8.5.6 (5763) указан пользователем.

## Все пункты меню

В таблицах описан код, который доступен для проверки. Работа декодеров на устройстве не проверялась. HLS означает HTTP Live Streaming (потоковую передачу по HTTP). HTTP означает Hypertext Transfer Protocol (протокол передачи гипертекста). URL означает Uniform Resource Locator (адрес ресурса). JSON означает JavaScript Object Notation (формат представления объектов JavaScript).

| Пункт меню | Идентификатор `player` | Модуль и интерфейс запуска | Где воспроизводится / кто запрашивает медиаданные | Ресурс при «Авто» | Граница подтверждения |
|---|---|---|---|---|---|
| Встроенный tvOS Pro | `tvospro` | `interaction/player.js`, `lampa://video?player=tvospro&src=…` | Нативная оболочка; конкретный сетевой клиент неизвестен | `urls.hls2` выбранного файла | Схема подтверждена кодом; движок и буфер недоступны |
| Встроенный tvOS Universal | `tvos` | Тот же модуль, `player=tvos` | Нативная оболочка; клиент неизвестен | HLS2 | Название не доказывает конкретный декодер |
| Встроенный tvOS Online | `tvosl` | Тот же модуль, `player=tvosav` | Нативная оболочка; клиент неизвестен | HLS2 | По строке `tvosav` нельзя доказать использование определённого системного движка |

| Встроенный | `inner` | `interaction/player.js` → внутренний `Video.url` / `PlayerVideo` | Веб-плеер Lampa: JavaScript и медиастек WebKit; запросы зависят от выбранного движка | HLS2 | Не равен трём нативным режимам tvOS |
| SVPlayer | `svplayer` | `interaction/player.js`, `svplayer://x-callback-url/stream?url=…` | Отдельное приложение SVPlayer | HLS2 | Адаптер ядра передаёт один адрес |

Не-Infuse пути учитывают явный формат; исторический выбор при отсутствии HLS2 может использовать другой настоящий HLS-адрес сервиса. Точная доставка в каждом пользовательском запуске неизвестна. Прямой файл Infuse не подменяется HLS. Предел качества не меняется. Для делегированных Apple-плееров отсутствие явно выбранного разрешения теперь заканчивается сообщением вместо подстановки большего разрешения; файлы выше сохранённого предела не запускаются.

У нативных режимов корневой объект целиком не сериализуется: схема содержит `src`, `playlist`, `segments`. Для обычного одиночного фильма плагин не добавляет `play.playlist`, поэтому корневые `timeline`, `title`, `voiceovers`, `subtitles` сами по себе в эту схему не попадают. Для сериала эти данные присутствуют внутри списка. Даже присутствие данных в JSON не доказывает их использование неизвестной сборкой оболочки. Политика обработки таких данных не менялась.

Передача Infuse соответствует документации Firecore для 8.4.7 и новее: действие `play`, одно кодирование каждого значения, имя и позиция; тесты сохраняют `&`, `?`, `%`, `+`, `=` после снятия внешнего кодирования. Документированных параметров буфера или запросов диапазонов в этом интерфейсе нет. Документированные обратные вызовы могли бы вернуть последний адрес/позицию либо ошибку, но требуют известного обработчика в приложении. В этой установке он не подтверждён. Просмотр не отмечается после одной передачи.

## Сопоставление VLC и Infuse

| Этап | VLC в «Авто» | Обычный Infuse |
|---|---|---|
| Материал | Поиск KinoPub и `/items/<id>` | То же |
| Выбор файла | `parseFiles` → `pickStream`, адрес HLS2 в выбранном разрешении | Прямой файл в доступном разрешении в пределах настройки; фиксируется его `file` |
| Свежесть | Адрес из загруженных данных материала | Для фильма с `file` один `/items/media-video-link?file=…&type=http`; для серии обновление материала, затем разрешение точного `file` |
| Старый ответ без `file` | Настоящее поле `urls` / `url` | Обновление `/items/<id>` и настоящее `urls.http` / `url.http`; неизменность физического файла без идентификатора доказать нельзя |
| Преобразования | Штатный `externalPlayer`: `Torserver.toPlayUrl` и `encodeURIComponent` | Проверка допустимости и `encodeURIComponent`; никакой замены домена, пути, расширения, подписи или HTTPS на HTTP |
| Адаптер | `Lampa.Player` → внешний адрес VLC | Прямой вызов документированной схемы Infuse |
| Медиазапросы | VLC | Infuse |

`Torserver.toPlayUrl` меняет `&preload` только если адрес содержит настроенный адрес TorrServer. По обычному адресу KinoPub это преобразование не выполняется. Отдельный адаптер Infuse ядра делает такую замену без этой проверки, поэтому существующий обход сохранён. Защитный адаптер плагина не запускает одновременно внутренний плеер.

Наблюдение пользователя о быстром VLC относится к иной цепочке доставки. Нет пары свежих ресурсов, ответов серверов и журналов двух приложений для одного фильма, года, издания, эпизода и качества. Поэтому сравнение подтверждено кодом и обезличенными сценариями, но не одинаковыми реальными сеансами. Номер разрешения сам по себе не устанавливает кодек, динамический диапазон или звук. При нескольких файлах одного разрешения сохраняется выбранный `file`; плагин не тестирует декодируемость каждого кодека.

## Подтверждённые дефекты и изменения

1. Обычный Infuse после обновления данных серии мог выбрать другой файл, включая новое разрешение; строгая привязка была только у HLS2-теста. Теперь выбранный файл и разрешение фиксируются до обновления. Исчезнувший файл не заменяется другим. Сохранён явный выбор качества списка, позиция и подпись.
2. Незавершённый запуск Infuse оставался активным после выбора другого плеера или материала. Теперь он отменяется; поздний ответ не разрешает ещё один файл и не открывает второе приложение.
3. Обработчик `onGroupButtons` зависел от порядка регистрации модулей. Последующий модуль мог восстановить меню. Ссылка на кнопку также захватывалась один раз. Теперь привязка восстанавливается после завершения события экземпляра, кнопка ищется заново; локальный наблюдатель охватывает замену элементов. Обработчики фокуса сохраняются, повторное нажатие блокируется до возврата, уничтожение карточки снимает наблюдатель и действие. Глобальное ядро и его прототипы не меняются.
4. Поиск принимал единственный результат и допускал соседний год/другой тип. Теперь нужен совпавший внешний идентификатор либо точные название, год и тип. Неоднозначные подходящие издания выбирает пользователь; чужой материал не открывается. Отсутствие совпадения сопровождается сообщением. Запросы ограничены по времени и защищены от повторных/устаревших ответов.
5. Веб-плеер Apple TV выполнял лишний GET (запрос получения) для отладочного чтения адреса как текста. При прямом файле тело не имело ограничения размера. Этот параллельный запрос убран на Apple TV. Infuse и делегированные плееры уже обходили его; он не объявляется причиной обрывов Infuse. Поведение Tizen сохранено.
6. Делегированный Apple-путь мог игнорировать отсутствующее явно выбранное разрешение или выйти за предел, когда подходящих файлов нет. Теперь запуск отклоняется без подмены.

Три сбоя карточки и четыре сценария Infuse сначала воспроизведены на прежнем коде, затем прошли после правок. Из этого не следует, что установлен конкретный конфликт расширений пользователя: состав и порядок модулей его оболочки недоступны. Простой сценарий ядра 335 на mx.10 уже проходил; новые проверки устраняют пробел в прежней модели тестов.

## Сеть и нерешённая причина остановок

Свежей разрешённой подписанной ссылки конкретного проблемного сеанса в текущих материалах нет. Ответы после перенаправлений, срок ссылки, необходимость дополнительных заголовков или cookies (данных сессии), зависимость от адреса выхода и запросы самого Infuse не получены. Реальные файлы и сегменты KinoPub в этой работе не загружались. Сетевые настройки, регион, авторизация, сервер, реклама и изображения эпизодов не менялись.

HLS2-тест mx.10 на устройстве завершился ошибкой «Сервер не сообщил размер файла». Переданный домен `api.service-kp.com` не определяет конечный узел или тип ответа. Поле `url` у `/items/media-video-link` содержит адрес; конечный ответ этого адреса без запроса неизвестен. 1269 мс подготовки и 1 мс передачи не измеряют старт декодера. 46 с после передачи не являются временем первого кадра. Повтор HLS2 без нового основания не предлагается, вывод о полной неподдержке HLS в Infuse не делается.

Проверены обезличенные локальные HTTP-сценарии утилиты `tools/probe_media.py`: начало, ненулевой/открытый диапазон и конец; неверный `Content-Range`, 200, 206, 416, изменение размера, `If-Range`, перенаправления с сохранением Range, отказ авторизации, истечение, ограничения чтения и времени. Не более 1024 байтов чтения на запрос; неверный частичный ответ/200 закрывается без чтения тела. До пяти основных запросов, один дополнительный для явного If-Range, до трёх переходов на запрос, общий предел 20 секунд. Смещение 205444144 применяется только к соответствующему файлу и допустимому размеру. Это испытания утилиты, не ответы KinoPub.

Диагностика в Lampa без доступного заголовка не доказывает отсутствие заголовка на сервере: возможны ограничения CORS, Cross-Origin Resource Sharing (совместного использования ресурсов разных источников). HLS-манифест и сегменты требуют отдельного исследования; размер манифеста не равен размеру фильма. Для известного `hls2-test` файловая проверка в плагине не запускается.

Точка продолжения: сопоставленный сеанс обычного Infuse с подтверждёнными материалом/файлом/качеством, цепочкой статусов и типом конечного ответа, допустимыми диапазонами и журналом Infuse; номер нативной сборки Lampa MX. До этого сервер, маршрут, срок ссылки и поведение клиента остаются гипотезами. Предзагрузка, ложные размеры, новые серверы, перекодирование и автоматические повторы не добавлены.

## Проверки и источники

`node --test tests/*.test.cjs` исполняет обезличенные модели плагина; `tests/core-adapters.test.cjs` дополнительно исполняет настоящие функции `start`, `externalPlayer`, `launchExternalPlayer`, `prepareInfuseLaunch` из указанной ревизии ядра. Если эталонные исходники недоступны, восемь таких проверок явно пропускаются, а не объявляются успешными. Для этого запуска эталон был доступен. Ни один тест не является измерением декодера или перемотки Apple TV.

Маршруты поиска, рекомендаций, избранного, истории и повторного открытия используют общий компонент полной карточки; проверены данные текущей карточки и его жизненный цикл. Реальные экраны каждого маршрута на Apple TV не пройдены. Browser plugin not available (плагин браузера недоступен). Playwright установлен, но исполняемый Chromium отсутствует; визуальная проверка не выполнена. Новые зависимости не устанавливались.
