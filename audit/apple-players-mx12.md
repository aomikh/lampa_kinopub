## Все пункты меню

В таблицах описан код, который доступен для проверки. Работа декодеров на устройстве не проверялась. HLS означает HTTP Live Streaming (потоковую передачу по HTTP). HTTP означает Hypertext Transfer Protocol (протокол передачи гипертекста). URL означает Uniform Resource Locator (адрес ресурса). JSON означает JavaScript Object Notation (формат представления объектов JavaScript).

| Пункт меню | Идентификатор `player` | Модуль и интерфейс запуска | Где воспроизводится / кто запрашивает медиаданные | Ресурс при «Авто» | Граница подтверждения |
|---|---|---|---|---|---|
| Встроенный tvOS Pro | `tvospro` | `interaction/player.js`, `lampa://video?player=tvospro&src=…` | Нативная оболочка; конкретный сетевой клиент неизвестен | `urls.hls2` выбранного файла | Схема подтверждена кодом; движок и буфер недоступны |
| Встроенный tvOS Universal | `tvos` | Тот же модуль, `player=tvos` | Нативная оболочка; клиент неизвестен | HLS2 | Название не доказывает конкретный декодер |
| Встроенный tvOS Online | `tvosl` | Тот же модуль, `player=tvosav` | Нативная оболочка; клиент неизвестен | HLS2 | По строке `tvosav` нельзя доказать использование определённого системного движка |
| Внешний | `tvosSelect` | Тот же модуль, `player=lists` | Выбор внутри оболочки; затем выбранный ею клиент | HLS2 до выбора в оболочке | Плагин не знает последующего выбора; это не отдельный декодер |
| VLC | `vlc` | `interaction/player.js`, `vlc-x-callback://x-callback-url/stream?url=…` | Отдельное приложение VLC | HLS2 | Штатный адаптер передаёт один адрес |
| Infuse | `infuse` | `docs/kp.js`: `launchInfuse` → `dispatchInfuse`; `infuse://x-callback-url/play` | Отдельное приложение Infuse | Свежая прямая ссылка `type=http` или обновлённое `urls.http` | Плагин обходит `core/infusePlayer.js`, который меняет `&preload` |

| VidHub | `vidhub` | `interaction/player.js`, `open-vidhub://x-callback-url/open?url=…` | Отдельное приложение VidHub | HLS2 | Используется `/open`, не предполагаемый `/play` |
| Встроенный | `inner` | `interaction/player.js` → внутренний `Video.url` / `PlayerVideo` | Веб-плеер Lampa: JavaScript и медиастек WebKit; запросы зависят от выбранного движка | HLS2 | Не равен трём нативным режимам tvOS |
| SVPlayer | `svplayer` | `interaction/player.js`, `svplayer://x-callback-url/stream?url=…` | Отдельное приложение SVPlayer | HLS2 | Адаптер ядра передаёт один адрес |

Не-Infuse пути учитывают явный формат; исторический выбор при отсутствии HLS2 может использовать другой настоящий HLS-адрес сервиса. Точная доставка в каждом пользовательском запуске неизвестна. Прямой файл Infuse не подменяется HLS. Предел качества не меняется. Для делегированных Apple-плееров отсутствие явно выбранного разрешения теперь заканчивается сообщением вместо подстановки большего разрешения; файлы выше сохранённого предела не запускаются.

У нативных режимов корневой объект целиком не сериализуется: схема содержит `src`, `playlist`, `segments`. Для обычного одиночного фильма плагин не добавляет `play.playlist`, поэтому корневые `timeline`, `title`, `voiceovers`, `subtitles` сами по себе в эту схему не попадают. Для сериала эти данные присутствуют внутри списка. Даже присутствие данных в JSON не доказывает их использование неизвестной сборкой оболочки. Политика обработки таких данных не менялась.

Передача Infuse соответствует документации Firecore для 8.4.7 и новее: действие `play`, одно кодирование каждого значения, имя и позиция; тесты сохраняют `&`, `?`, `%`, `+`, `=` после снятия внешнего кодирования. Документированных параметров буфера или запросов диапазонов в этом интерфейсе нет. Документированные обратные вызовы могли бы вернуть последний адрес/позицию либо ошибку, но требуют известного обработчика в приложении. В этой установке он не подтверждён. Просмотр не отмечается после одной передачи.

## Сопоставление VLC и Infuse

| Этап | VLC в «Авто» | Обычный Infuse |
|---|---|---|
| Материал | Поиск KinoPub и `/items/<id>` | То же |
| Выбор файла | `parseFiles` → `pickStream`, адрес HLS2 в выбранном разрешении | Прямой файл в доступном разрешении в пределах настройки; фиксируется его `file` |
| Свежесть | Адрес из загруженных данных материала | Для фильма с `file` один `/items/media-video-link?file=…&type=http`; для серии обновление материала, затем разрешение точного `file` |
| Старый ответ без `file` | Настоящее поле `urls` / `url` | Обновление `/items/<id>` и настоящее `urls.http` / `url.http`; неизменность физического файла без идентификатора доказать нельзя |
| Преобразования | Штатный `externalPlayer`: `Torserver.toPlayUrl` и `encodeURIComponent` | Проверка допустимости и `encodeURIComponent`; никакой замены домена, пути, расширения, подписи или HTTPS на HTTP |
| Адаптер | `Lampa.Player` → внешний адрес VLC | Прямой вызов документированной схемы Infuse |
| Медиазапросы | VLC | Infuse |

`Torserver.toPlayUrl` меняет `&preload` только если адрес содержит настроенный адрес TorrServer. По обычному адресу KinoPub это преобразование не выполняется. Отдельный адаптер Infuse ядра делает такую замену без этой проверки, поэтому существующий обход сохранён. Защитный адаптер плагина не запускает одновременно внутренний плеер.

Наблюдение пользователя о быстром VLC относится к иной цепочке доставки. Нет пары свежих ресурсов, ответов серверов и журналов двух приложений для одного фильма, года, издания, эпизода и качества. Поэтому сравнение подтверждено кодом и обезличенными сценариями, но не одинаковыми реальными сеансами. Номер разрешения сам по себе не устанавливает кодек, динамический диапазон или звук. При нескольких файлах одного разрешения сохраняется выбранный `file`; плагин не тестирует декодируемость каждого кодека.

## Дополнительная проверка официального VLC

Официальное зеркало VideoLAN, `videolan/vlc-ios@25c7a7035b119fc1f574db411c382d7b285f18fc`, получено только для чтения. Установленная пользователем версия VLC неизвестна, поэтому это подтверждение актуального исходного пути, а не побайтовая проверка его приложения.

- [`AppleTVAppDelegate.m`, `application:openURL:options:`](https://github.com/videolan/vlc-ios/blob/25c7a7035b119fc1f574db411c382d7b285f18fc/Sources/App/tvOS/AppleTVAppDelegate.m) перебирает обработчики адресов.
- [`URLHandler.swift`, `XCallbackURLHandler.performOpen`](https://github.com/videolan/vlc-ios/blob/25c7a7035b119fc1f574db411c382d7b285f18fc/Sources/Helpers/Network/URLHandler.swift) принимает `vlc-x-callback`, действие `stream`, вызывает `handlePlay`. `parseURL` разбирает внешний запрос; `getURLForValue` снимает кодирование всего вложенного адреса при наличии закодированного `://`. Вложенные `&`, `=` и `%` поэтому должны кодироваться на внешней границе, как делает Lampa.
- `VLCURLHandler.play` создаёт `VLCMedia(url:)`, список из одного элемента и вызывает `PlaybackService.playMediaList`. Это потоковый запуск, не действие `download`. Сам VLC также знает `sub` и обратные вызовы, но адаптер Lampa в данной ветке их не передаёт.
- [Первичное описание схемы VideoLAN](https://mailman.videolan.org/pipermail/vlc-devel/2014-October/099830.html) согласуется с исходниками. Wiki VideoLAN вернула ошибку доступа; вывод не основан на её недоступном содержимом.

Десять пунктов меню подтверждены `src/interaction/settings/params.js`, ветка `Platform.is('apple_tv')`, настройка `player`. Наличие `tracyplayer` среди схем `start` не добавляет его в это меню: в списке Apple TV его нет. Выбор меню оболочки `tvosSelect` остаётся границей наблюдения.

Сервер выбирает KinoPub при выдаче адреса с учётом настроек устройства сервиса. В пути запуска нет отдельного выбора региона для Infuse или VLC. `setupRegion` вызывается отдельным действием настроек и не блокирует запуск. Указанный в отчёте узел является начальным: перенаправление может изменить сервер. Настройки региона, сети и репозиторий Shadowrocket в этой работе не менялись.

## Что добавлено в mx.12

`docs/kp.js`, `LaunchTrace`, `launchInfuse`, `dispatchInfuse`, `toPlayElement`, `append`:

- По умолчанию выключенная **Запись этапов запуска**; отдельный **Отчёт последних запусков** в настройках KinoPub на Apple. Последние восемь попыток только в памяти. Выключение очищает записи и таблицу сравнения. Никакой отправки на лог-сервер или сохранения отчёта в хранилище.
- Монотонные времена, если WebKit предоставляет `performance.now`: `item_ms` (обновление материала), `build_ms` (сборка списка), `link_ms` (разрешение файла), `prepare_ms` (вся подготовка), `dispatch_ms` (от готовой ссылки до вызова передачи). При отсутствии монотонных часов используется Date.now. Завершённый этап без ожидания может иметь 0, отсутствовавший или незавершённый отмечен `null`/`?`.
- Обычный фильм не получает искусственный этап обновления материала. Сохранены отдельные результаты отмены, тайм-аута, ошибки подготовки и синхронного исключения при передаче. Поздний ответ не восстанавливает очищенную запись.
- KinoPub ID, год, сезон/серия, разрешение, фактически выбранное поле доставки. Последнее берётся из выбора `pickStream`, включая настоящий резервный HLS4/HLS, а не угадывается по расширению `.mp4`.
- Метки `F` означают равенство строк `files[].file`; `U` означают точное равенство адресов, включая подпись. Назначаются сравнением в памяти, не хешированием секрета. В отчёте нет пути, запроса, вложенного адреса, токена или имени файла. Таблица ограничена 64 значениями; метки сравнимы только в одном сеансе. Равенство идентификатора не является проверкой байтов фильма; разные подписанные адреса могут вести к одному файлу.
- Показаны позиция и число элементов объекта/схемы в наблюдаемой границе. У Infuse граница непосредственно `window.location.assign`; у остальных `Lampa.Player.play`. Вторая граница не подтверждает, что нативная оболочка получила или использовала все поля. У `inner` ядро ещё может выбрать сохранённое качество из карты; последующий URL отчёт не перехватывает.
- При проверке подготовленного кода воспроизведены и исправлены два дефекта самого отчёта: появившийся после обновления метаданных идентификатор файла теперь берётся из окончательного объекта Infuse; разовый выбор `lampa` правильно отображается как `inner`. Отсутствующий `build_ms` явно равен `null`. Два новых теста сначала завершились ошибками, затем прошли. Это не причины медленного старта.

**Новые строки диагностики не исправляют скорость.** Выбор файлов, подписи, качество, позиция, аудио, субтитры, сетевые настройки и существующие исправления «Смотреть» не менялись. Подготовка объекта и таймеры не скачивают медиа. Плагин не наблюдает открытие окна Infuse, первый кадр, остановку декодера или длительность просмотра. Статус `submitted` означает только вызов передачи.

| Проверки mx.12 | Искусственные часы 430 + 670 = 1100 мс подтверждают раздельный учёт | Это тестовые значения, не замер сети или Apple TV |
| До/после mx.12 на Apple TV | Данных нет | Улучшение скорости, дорожки и перемотка не подтверждены |

Свежего разрешённого подписанного ресурса этого пользователя нет. Поэтому конечный статус после перенаправлений, MIME-тип, Content-Length, Content-Range, 416, изменяющийся размер, срок действия, cookies/заголовки и зависимость от адреса выхода не проверялись на KinoPub. `api.service-kp.com` сам по себе не доказывает служебный ответ вместо медиа. Адрес выдаётся из поля `url` ответа `/items/media-video-link` без замены домена, HTTPS, пути или подписи. Прямой запуск **того же действующего адреса** в Infuse в обход Lampa не выполнен: нет самого адреса и доступа к устройству.

Медленный первый кадр и остановка около 30 с остаются отдельными симптомами. Гипотезы: ожидание ответов диапазонов у прямого файла; особенности чтения/анализа контейнера Infuse; перенаправление, истечение или ответ авторизации; различие маршрута клиентов. Ни одна не установлена. Сравнение должно сначала подтвердить материал/год/эпизод/качество/F/доставку, затем исследовать конечный ответ и журнал Infuse. Если малые `prepare_ms` и `dispatch_ms` сочетаются с долгим ожиданием кадра, это локализует остаток после наблюдаемой границы, но ещё не выбирает между Infuse, оболочкой и источником.

Готовая `tools/probe_media.py` ограничивает запросы, время и чтение (до 1024 байтов за запрос), проверяет начало/ненулевой/открытый/конечный диапазоны и соответствие Content-Range. Неверный 206, 200 вместо диапазона, авторизация и 416 не считаются успехом. Реальные фильмы не загружались; старое смещение 205444144 к другому файлу не применялось. HLS-манифесты и сегменты не исследовались; критерии целого файла к ним не применялись. Браузерная невидимость заголовка из-за CORS не равна его отсутствию на сервере.

### Контроль одного адреса и проверка гипотез

Базовый прогон сохраняет работающие настройки. Отдельная серия опытов может временно использовать явный `http` для VLC на Apple TV и обычный Infuse, с одним файлом, разрешением и позицией. После неё вернуть исходный формат. Равная F и разные U подтверждают только идентификатор файла, но не идентичность подписанной ссылки. Нельзя называть такое сравнение проверкой одного адреса.

Строгий контроль требует одного действующего адреса: вручную открыть его в Infuse, затем этот же адрес в VLC на том же Apple TV. Адрес получают из авторизованного сеанса и используют приватно; в GitHub и отчёт его не помещают. В этой работе такой адрес не предоставлен и контроль не выполнен. Нельзя заменять его повторным получением ссылки или похожим названием фильма. Для одинаковой позиции в VLC её придётся выставить отдельно, поскольку текущий адаптер Lampa не передаёт `position`.

| Гипотеза | Что может её подтвердить или ослабить |
|---|---|
| Долгая подготовка в плагине | Большие `item_ms` или `link_ms`; отделить обновление авторизации. Короткая подготовка при долгом первом кадре переносит поиск за границу плагина |
| Особенности прямого файла или его сервера | Длительные/ошибочные ответы на ненулевые диапазоны, смена размера, ответ авторизации; сравнить тот же адрес в VLC |
| Особенности Infuse или передачи оболочкой | Быстрый тот же адрес в VLC, медленный в Infuse; ручной запуск того же адреса в Infuse помогает отделить передачу из Lampa |
| Подготовка списка сериалов | Фильм и серия сравниваются отдельно; число переданных элементов видно в отчёте. Без замера обработка списка самим Infuse неизвестна |
| Остановка после начала просмотра | Отдельный журнал клиента и время после первого кадра; успешный старт не исключает последующий отказ диапазона, истечение ссылки или недостаточную скорость |

Для уверенного сравнения повторить каждый выбранный сценарий три раза, чередуя плееры, с одним состоянием приложения и одинаковой позицией. Сначала сохранить отчёт, затем закрывать Lampa, иначе измерения пропадут. Для серий следующий адрес передаётся из свежего списка заранее; плагин не может обновить его внутри уже запущенного Infuse. Истечение ссылки поздней серии пока не наблюдалось, но этот предел интерфейса остаётся.
