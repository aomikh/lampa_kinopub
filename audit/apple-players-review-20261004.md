# Apple TV: фактические пути воспроизведения, mx.9

Проверено 2026-10-04. Исходная main: `71b15e3900f4c489992ef5b0d28efb71b8105206`. Ядро для сверки: yumata/lampa-source `b4a13b6af7fe2f3bbbcb91f4eb434ab3378f8d5d` (335). Версии установленной оболочки Lampa MX, tvOS и внешних приложений неизвестны. Пользователь сообщил, что встроенные Pro / Universal / Online запускаются быстро. Это наблюдение до изменения кода, без сопоставленных сетевых ответов или измерения первого кадра.

## Все пункты показанного меню

| Пункт | Значение Lampa / штатный запуск | Путь KinoPub при «Авто» | Существенное ограничение |
|---|---|---|---|
| Встроенный tvOS Pro | `tvospro`, `lampa://video?player=tvospro` | HLS2 | Реализован оболочкой; название Pro не устанавливает декодер или превосходство качества |
| Встроенный tvOS Universal | `tvos`, `lampa://video?player=tvos` | HLS2 | Значение по умолчанию в проверенном ядре; настройки буфера не раскрыты |
| Встроенный tvOS Online | `tvosl`, `lampa://video?player=tvosav` | HLS2 | `tvosav` является параметром, а не достаточным доказательством конкретной реализации движка |
| Внешний | `tvosSelect`, `lampa://video?player=lists` | HLS2 | Открывает выбор в оболочке; не самостоятельный декодер. Последующий выбор приложения не известен плагину |
| VLC | `vlc-x-callback://x-callback-url/stream?url=` | HLS2 | Адаптер ядра передаёт только URL, не позицию и не внешние субтитры |
| Infuse | `infuse://x-callback-url/play` через адаптер плагина | Свежий прямой `urls.http` / `/items/media-video-link`, фактический `file` | Подпись сохраняется; ошибка доступа к ненулевому диапазону не устранена сменой других адаптеров |
| SenPlayer | `SenPlayer://x-callback-url/play?url=` | HLS2 | Приложение имеет расширенные возможности, но проверенный адаптер ядра передаёт только URL |
| VidHub | `open-vidhub://x-callback-url/open?url=` | HLS2 | Сохранён совместимый `/open`; позиция в этом интерфейсе не поддерживается |
| Встроенный | `inner`, веб-плеер Lampa | HLS2 | Это не один из трёх нативных tvOS-режимов; остаются внутренние обработчики и восстановление потока |
| SVPlayer | `svplayer://x-callback-url/stream?url=` | HLS2 | Производитель указывает отсутствие HDR-вывода и ограничения 4K с интерполяцией кадров; не основной выбор для сохранения исходного HDR |

HLS означает HTTP Live Streaming, поток по HTTP из сегментов. HTTP означает Hypertext Transfer Protocol, протокол передачи гипертекста. Различие HLS и прямого файла подтверждено логикой выбора при «Авто», но конкретные ресурсы пользовательских запусков не получены. Явная настройка формата имеет приоритет у не-Infuse путей; при отсутствии нужного поля сохраняется прежняя цепочка HLS-вариантов. Глобальный предел качества сохраняется. Если HLS-ссылка является общим мастер-плейлистом, выбор файла в API не доказывает фактический битрейт декодера.

Нативные схемы передают `src`, JSON-плейлист и `segments`. В плагине сохранены доступные метаданные, включая timeline, аудио и субтитры. Это не доказательство, что установленная оболочка использует все поля. Generic внешние схемы ядра передают только URL. Поэтому сохранение subtitle/timeline в объекте не объявляется исправленной синхронизацией прогресса VLC/SenPlayer/VidHub/SVPlayer. Для прямого файлового пути Infuse нужен выбор **Infuse**, а не выбор Infuse внутри общего меню «Внешний»: плагин не может предугадать последующий выбор оболочки.

## Подтверждённые дефекты и минимальное изменение

1. `dumpStreamManifest()` вызывался перед каждым не-Infuse запуском. Это дополнительный GET без ограничения размера тела, с тайм-аутом 5 секунд. При явном `http` он мог читать видео как текст для отладки. mx.9 пропускает запрос для делегированных Apple-плееров. Не утверждается, что он был причиной прежнего зависания Infuse: путь Infuse уже обходил его.
2. `Lampa.Player.play()` заменяет `data.url` из карты `data.quality` по общему запомненному качеству. Теперь делегированный объект не содержит этой карты: ядро получает уже выбранную ссылку. Устаревшая автоматическая подпись строки не ограничивает максимум для нового Apple-плеера; явный выбор и сохранённый предел остаются в силе. Качество выбранного эпизода совпадает в основном объекте и плейлисте.
3. Внутренние `pendingVoice` и `play.error` назначались также плеерам оболочки и внешним приложениям. Они отключены только на этих путях. Пассивные метаданные аудио/субтитров сохранены. Нет новой схемы запуска, нового сервера, теста сети перед запуском или изменения Tizen.
4. `item.mark()` и callback могли обозначить просмотр только из-за передачи. Для делегированного пути этого больше нет. Синхронный отказ `Lampa.Player` показывает KP-A1 один раз; асинхронные ошибки открытого приложения не перехватываются и повторный запуск не выдумывается.

Путь Infuse оставлен с прямым файлом. В официальном выпуске 8.5.6 от 30 сентября 2026 появилась базовая поддержка M3U/M3U8. Это не достаточное подтверждение конкретного варианта HLS KinoPub, аудиодорожек, перемотки и версии установленного клиента. Поэтому «Infuse никогда не поддерживает M3U8» не используется как утверждение, но неподтверждённый HLS автоматически в него не передаётся.

VidHub документирует новый `/play` с позицией, именем, субтитрами и обратными вызовами. Старый `/open` поддерживается на Apple TV. Номер установленного приложения и зарегистрированный обработчик возврата Lampa MX неизвестны, поэтому адаптер не заменён вслепую. SenPlayer сообщает о сегментированном кэше и поддержке позиции через URL Scheme, однако точные параметры и версия пользователя не подтверждены. VLC остаётся возможным контрольным плеером. Рекламные заявления приложений не являются сравнением скорости этой связки.

Практический выбор: оставить тот встроенный режим, на котором пользователь уже подтвердил быстрый запуск. На снимке выбран Online. Все три можно сравнить на одном материале; нет оснований объявить Pro быстрее Universal/Online или считать их качество одинаковым для любого файла. Проверять реальное разрешение, динамический диапазон, дорожки и продолжение отдельно. Размер фильма сам по себе не определяет время запуска; это изменение не гарантирует одинаковую скорость для любого файла.

## Проверки и границы

Новые обезличенные тесты сначала обнаружили дефекты на mx.8, затем прошли на mx.9. Проверены все восемь делегированных вариантов, отсутствие дополнительного GET, одно обращение к адаптеру, максимум/явное качество/сохранённый предел, смена плеера после построения списка, выбранный эпизод, подпись и позиция, отсутствие отметки просмотра, отказ без повторов и разовый возврат во внутренний плеер. Общий результат: 95 JavaScript, 16 Python HTTP, 20 smoke; синтаксис и diff проверены. Существующие проверки Infuse, Range, Tizen, карточки и изображений сохранены.

Тестовый `internal` в runtime.cjs обозначает вызовы Lampa.Player, а не запуск внутреннего декодера на Apple TV. Приложения не запускались из Codex; их скорость, воспроизведение, HDR, перемотка и прогресс после mx.9 не проверены. Ни реальный фильм, ни его сегменты для исследования не скачивались. Настройки Shadowrocket, регион, токены, реклама и изображения не менялись.
