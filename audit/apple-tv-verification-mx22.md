# Проверка mx.22 на Apple TV

Это необходимые физические проверки, которые в подготовленной ветке ещё не выполнялись. Тестирование с имитацией Lampa их не заменяет.

## Подготовка

Запиши модель Apple TV, версию/build tvOS и Lampa MX, адрес/версию загружаемого ядра и Infuse 8.5.6 (5763). Установи kp.js конкретного проверяемого коммита отдельной ветки, оставь одно расширение KinoPub, полностью перезапусти Lampa. Номер должен быть 1.0.73-mx.22 в Настройки → KinoPub → «Infuse: последняя передача» после запуска.

Выбери три материала: несколько языков; хотя бы две русские студии с явно различимым текстом/голосом; единственная дорожка. Добавь сериал с двумя следующими сериями, субтитрами и несколькими разрешениями. Зафиксируй item id, season/episode, максимальное разрешение и язык/студии по API. Для HLS отдельно проверь дорожки группы выбранного video variant по свежему master. Число audios API не равно автоматически числу дорожек этого источника.

Используй существующий журнал Lampa и журнал воспроизведения Infuse, если он доступен в этой версии. После перехода в Infuse журнал Lampa перестаёт описывать CDN-запросы. Сеть и Shadowrocket не изменяй ради этой проверки. Токены, коды активации, полный payload с подписью и исходные URL храни только локально.

## Независимые устройства

1. До привязки зафиксируй id и название каталога. Подтверди **только если профиля Infuse ещё нет** отдельный код через kino.pub/device. Для сохранённого mx.21 профиля просто запусти фильм.
2. На сайте KinoPub должны быть две разные записи/id. Для интеграции ожидается «Lampa MX / Infuse / Apple TV», hardware Apple TV, software Lampa MX / kp.js 1.0.73-mx.22 / известное ядро / external Infuse. Сравни описание с `/device/info` именно профиля Infuse после notify. Не выдавай изменение названия за смену client type.
3. Повтори запуск, закрой и снова открой Lampa, запусти другой фильм. Число устройств не должно увеличиться, код не должен запрашиваться заново. Каталог сохраняет исходное имя и авторизацию.
4. Дождись естественного истечения access token либо проверь на отдельно выделенном тестовом профиле. Выполни два запроса параллельно: один refresh, оба запроса завершаются с новым access; новый refresh token сохранён. Не редактируй рабочие токены ради теста.
5. Отмени окно нового кода, открой его снова: старый ответ не закрывает новое окно и не записывает grant. Временная потеря сети во время info/notify/refresh не удаляет профиль; повтор после восстановления не требует нового кода.
6. На тестовом профиле отключи только Infuse: каталог продолжает работать, поздний ответ не возвращает Infuse. Отдельно проверь выход каталога при работающем профиле Infuse. Локальный выход не объявляй серверным удалением записи. Отзыв устройства в KinoPub проверяй только для тестовой записи.

## Infuse: длительность и сравнение

Выполни два независимых просмотра одного проблемного файла на неизменённом маршруте. Продолжительность **каждого**: минимум 30 минут и минимум на 10 минут больше прежнего воспроизводимого интервала до остановки, если тот превышал 20 минут. Не сворачивай Infuse для «поддержания» Lampa.

1. Запуск плагином: получить item и file через профиль Infuse, подтвердить максимальное разрешение, `type=http` и отсутствие более низкого файла. Зафиксировать UTC получения ссылки и открытия плеера. Смотреть непрерывно до требуемого времени; затем seek вперёд/назад, пауза/возобновление, выход и продолжение. Для сериала проверить следующую серию.
2. Сравнение: в новой попытке получить одну свежую ссылку. Приватно сохранить полный URL до кодирования и декодированный один раз параметр url из infuse://. Они должны совпадать посимвольно, включая плюс, процентное кодирование, подпись и параметры. Сначала проверить короткий ручной запуск именно этой строки через поддерживаемый способ открытия URL в Infuse, затем запуск плагином той же строки. Одинаковый URL означает одинаковый файл/подпись, но ручной UI может кешировать предыдущую запись: проверь имя и позицию.
3. Для второго длительного просмотра получить новую свежую ссылку и запустить её вручную. Так сравнивается способ запуска без эффекта возраста подписи. Сравнение спустя 30 минут старой ссылки с новой ссылкой считать отдельной проверкой срока действия, а не чистым сравнением способов запуска.
4. Если текущий Infuse не предоставляет ручной ввод URL, открыть тот же документированный infuse:// адрес из другой разрешённой точки системы. Это сравнит передачу плагином и прямой deep link, но не подменит проверку отличающегося ручного интерфейса Infuse.

Сразу после остановки, без переподписания, проверить **ту же** ссылку ограниченными запросами с компьютера в той же сети. Затем отдельно получить свежую ссылку того же устройства/файла и сравнить. Это не копирует маршрут самого Apple TV и не заменяет его HTTP-журнал.

```bash
python3 tools/probe_media.py < /private/current-link.txt > /private/probe-after-stop.json
python3 tools/inspect_hls.py < /private/current-master-url.txt > /private/master-tracks.json
```

Первый инструмент: до 20 секунд суммарно, по 1024 байта из корректного 206, HEAD и диапазоны начала/середины/открытого диапазона/суффикса. Полный фильм не скачивается. При 200, отклонённом диапазоне или ошибке тело не читается. Необязательный `--offset` использовать только для фактического смещения остановки этого файла. Необязательный `--if-range` использовать только для реально наблюдённого валидатора и хранить приватно. Отказ HEAD сам по себе не означает отказ GET. Второй инструмент читает только manifest, до 128 KiB + 1 байт и 15 секунд, без сегментов.

Инструменты показывают статус отдельно: 401/403, 410, 429, 5xx, timeout/reset; для 206 сравни Content-Range, Content-Length, общий размер и offset. Стабильный локальный probe не доказывает исправность Range Infuse. Изменение работоспособности после OAuth refresh также само по себе не доказывает отзыв старой подписи.

## Audio: отдельная матрица для трёх режимов

Повтори полный набор **для Online (tvosl → tvosav), Universal (tvos → tvos) и Pro (tvospro)**. В существующей настройке «Формат потока» выбери «Авто» для этой части теста; Infuse независимо остаётся HTTP.

| Действие | Критерий прохождения |
|---|---|
| Начальный запуск каждого из трёх материалов | звук/видео есть, источник текущего фильма/серии, меню содержит фактические дорожки группы master |
| Русский → другой язык → обратно | реально слышен другой язык, затем исходный; выделения меню недостаточно |
| Русская студия A → B → A | реально меняются голоса/текст по заранее выбранной сцене; записи с одним языком различимы |
| Единственная дорожка | одна действительная дорожка, нет вымышленных дубликатов |
| Смена при выбранном качестве | качество не сбрасывается вследствие команды; фактическое HLS-разрешение зафиксировано по журналу/информации плеера |
| Смена с включёнными субтитрами | выбранные субтитры и синхронизация сохраняются |
| Seek ±5 минут после смены | тот же язык/студия, видео и звук продолжаются, нет перезапуска другой серии |
| Пауза/возобновление, закрытие/продолжение | корректная позиция; отдельно отметить, сохранила ли оболочка звук и субтитры |
| Следующая серия | правильный episode, рабочий источник; отдельно отметить, сохраняется ли студия, когда она реально присутствует |

Если меню отсутствует или звук не меняется, этот режим **не прошёл** проверку. Сохранить master-топологию и нативный журнал. Плагин этой ветки не предоставляет выдуманной команды audioTrack и не предлагает фиктивный выбор перед запуском. Для реализации последнего нужен подтверждённый source с выбранной озвучкой или API оболочки, которых сейчас нет. Если master содержит все дорожки и сам плеер их не обслуживает, дальнейшее исправление относится к оболочке.

Регрессии: отдельный короткий запуск Infuse и VLC; Apple inner/lampa с обнаруженным меню аудио и переключением туда/обратно; iPhone/iPad с сохранённым входом, deep link, resume и субтитрами; Tizen с прежним форматом и существующими настройками proxy, выбором двух озвучек, seek и следующей серией. Тесты JS не означают прохождение этой матрицы.

## Нужные журналы

- UTC начала/остановки, возраст подписи в момент остановки, item/season/episode, качество, фактический плеер и версия/build. Два способа запуска отмечать отдельно.
- Обезличенный Lampa-журнал: профиль и deviceId, info/notify/settings и их HTTP/body status, получение item/resolver, этап последней передачи. accessExpiresAt является сроком access token, не сроком ссылки.
- Обезличенные `/device/info` обоих профилей до/после, с title/hardware/software/id/is_browser и выбранными документированными настройками. Токены и headers Authorization не пересылать.
- HTTP-журнал **самого Infuse или видеосервера** для запроса после остановки: время, request id, HTTP status, Range, Content-Range, Content-Length, Accept-Ranges, редиректы, Date/Expires/Cache-Control, ETag/Last-Modified и вид сетевого разрыва. Полные подписанные пути хранить приватно. Сведения только о CONNECT/TCP закрытии не отвечают на вопрос о 403.
- Для каждого tvOS-режима: обезличенный вывод HLS inspector, снимок настоящего меню с языками/студиями, последовательность A→B→A и подтверждение слышимого изменения, позиции/качества/субтитров/следующей серии. При наличии журналов оболочки: события выбора и перечисленные media/audio streams.

Общий итог устройства записывать отдельно от автотестов: «прошло», «не прошло», «не проверено» для каждого пункта. Для признания причины истечения подписи нужен наблюдаемый отказ прежнего URL и успешная свежая ссылка при контролируемых остальных условиях, желательно с объяснением/журналом KinoPub.
