## Проверено по коду и конфигурации

Источник исполняемого плагина и одновременно публикуемый файл: `docs/kp.js`. Генератора, сборщика или отдельного исходника kp.js нет. GitHub Pages использует main и /docs; последний успешный процесс до правки: [37494662399](https://github.com/aomikh/lampa_kinopub/actions/runs/37494662399). Полученный по постоянному адресу mx.18 совпал с исходником по байтам: 222834 байта, SHA-256 `2705ae24de90d015d9fc3a080e23e306cb2f809eeea0788a06bdf8d61f9173d6`. Это подтверждает публикацию, а не установку на Apple TV.

Все пять исходных фактов mx.18 подтверждены: `preferredFormat('infuse')` возвращал http; обычное Авто выбирало hls2; `infuseFileUrl` отклонял узнаваемые манифесты; запуск получал новую файловую ссылку с type=http; `buildInfuseUrl` также использовал файловый валидатор. У остальных плееров исторически есть резервные HLS-форматы, поэтому Авто само по себе не гарантирует фактическое поле hls2 при его отсутствии.

HLS означает HTTP Live Streaming (потоковую передачу по HTTP). HTTP означает Hypertext Transfer Protocol (протокол передачи гипертекста). HLS2 здесь обозначает поле KinoPub, а не вторую версию протокола HLS. Официальная [документация KinoPub](https://kinoapi.com/api_video.html) описывает `files[].file`, `urls.hls2`, оба представления urls/url, и `items/media-video-link` с type=http|hls|hls2|hls4. Адрес HLS может оканчиваться на mp4; расширение не устанавливает тип ответа.

В mx.19 добавлен отдельный параметр Apple `kp_infuse_format_v1`:

| Значение | Поведение |
|---|---|
| http, по умолчанию | Прежний прямой файл, режим совместимости |
| hls2, явный выбор | Эксперимент HLS2, как поле при Авто Online |
| Любое другое | Ошибка, без подстановки другого формата |

Общая настройка формата и контекстный override не переключают Infuse. Старое `kp_infuse_delivery=hls4` не включает новый эксперимент. Параметры аккаунта, предел качества и выбор плеера не мигрируются.

Путь HLS2: `preferredFormat` → строгий `pickStream` → `toPlayElement` с `_kpFormat=hls2` и фиксацией файла/качества → свежая карточка того же материала → проверка фильма либо сезона/эпизода, того же файла и качества → отдельный `KP.hls2VideoLink` с type=hls2 → отдельный HLS-валидатор → `buildInfuseUrl` → `dispatchInfuse`. Файловый `KP.mediaVideoLink` с type=http на этом пути не используется.

При отсутствующем HLS2 в заполненной карте ссылок, исчезнувшем качестве, сменившемся файле, неоднозначных файлах одного качества, ошибке или тайм-ауте запуск прекращается. Метаданные без ссылок, но с точным файловым идентификатором позволяют запросить нужный формат штатным интерфейсом. Без точного file эксперимент прекращается. Узнаваемые http/hls/hls4, промежуточный manifest-proxy и DASH отвергаются HLS-валидатором. Непрозрачные ссылки допускаются только с происхождением из поля hls2 или ответа на type=hls2. Тип их фактического HTTPS-ответа не измерен.

Подписанный внутренний адрес не разбирается для повторной сериализации, не декодируется и не изменяется. Он кодируется один раз как значение параметра внешней схемы Infuse. Фильм, качество и файл не подменяются; конвертера и перекодирования нет.

Для списка серий сохраняются порядок, начальные позиции и включённые внешние субтитры из свежей карточки. На первой недоступной серии список заканчивается; перескока через неё нет. Сохраняются ограничения 40 элементов и 65536 символов внешней схемы. При нехватке данных не добавляются старые ссылки. Следующие ссылки подготовлены при запуске; обновлять их после истечения срока внутри Infuse плагин не может. Тогда серию нужно снова открыть из Lampa.

Остальные плееры и обычный файловый путь сохранили выбор источника и передачу. Из общей диагностики скрыты уникальные имена видеохостов; остаются только публичные служебные имена и группы msk-static-05/06/07 без уникального поддомена.

## Совместимость и ограничения

По последнему сообщению пользователя Infuse: 8.5.6 (5763); нынешняя установка не опрошена. [Интерфейс Firecore](https://support.firecore.com/hc/en-us/articles/215090997-API-for-Third-Party-Apps-Services), прочитан 07.10.2026, доступен с Infuse 8.4.7 на Apple TV и поддерживает повторяющиеся url/position/filename/sub. Он не подтверждает декодирование конкретного HLS2 KinoPub и не документирует выбор локального прокси или сетевого стека через схему запуска.

В [официальном выпуске 8.5.6](https://community.firecore.com/t/infuse-8-5-6-now-available/60886) заявлена базовая поддержка M3U/M3U8. [Пояснение Firecore](https://community.firecore.com/t/m3u-playlist-support/14097/254), проверенное через официальный JSON темы 07.10.2026, ограничивает поддерживаемые разновидности ссылок/потоков. Это не подтверждение пригодности конкретного ресурса KinoPub.

Исторический тест mx.10 на устройстве завершился ошибкой «Server didn't report the size of the file»; данные сохранены в `audit/infuse-mx10-device-result-20261004.json`. В mx.13 подтверждалась передача выбранного поля hls2, но устойчивое воспроизведение не подтверждалось (`audit/infuse-mx13-device-result-20261005.json`). Новая ветка не объявляется исправлением этих результатов. По текущему запросу разрешён именно обратимый эксперимент, а не принудительный HLS2.

Соответствие аудиодорожек, внешних/встроенных субтитров, многоканального звука, HDR (High Dynamic Range, расширенного динамического диапазона) и Dolby Vision между файловым ресурсом и HLS2 не установлено. HLS2 может предоставлять другой набор дорожек. В описании режима это указано до переключения. Плагин не изменяет разрешение, аудио, манифест или режим изображения и не обещает эквивалентность на стороне сервиса/декодера. Существующее ограничение интерфейса: один внешний субтитр на видео; сдвиг субтитров не передаётся. Выбор дорожки выполняется средствами Infuse, если она присутствует.

В логах и локальной записи последней попытки фиксируются версия, фактически выбранное поле, качество и этап подготовки/передачи. Запись «вызов передачи завершён» означает лишь возврат из `window.location.assign`. Она не означает открытие Infuse, первый кадр, просмотр или отсутствие ошибки. В настройках доступен просмотр последней записи без сетевого запроса. Ссылки, токены, пути файлов и уникальные имена видеохостов в неё не записываются.

## Сетевой вход: не подтверждён

По фактам предыдущих журналов, приведённым пользователем в текущем задании, оба плеера использовали PROXY через выбранный узел. Для Infuse наблюдались tcp stream и локальные закрытия около 20,5 секунды; для Online: proxy stream, loopback=>1 и одно соединение более 15 минут. Пользователь сообщил об отсутствии зависаний Online. Прежние журналы в этой работе заново не расшифровывались. Открытый сокет не подтверждает непрерывную дозагрузку; HTTPS-журнал не подтверждает манифест, Range или битрейт.

[NEProxySettings](https://developer.apple.com/documentation/networkextension/neproxysettings) описывает системные настройки HTTP-прокси в конфигурации виртуальной частной сети. [NEPacketTunnelProvider](https://developer.apple.com/documentation/networkextension/nepackettunnelprovider) отдельно описывает виртуальный пакетный интерфейс и связанные с ним настройки маршрутов/прокси. Оба интерфейса доступны на tvOS с версии 17. Эти официальные страницы прочитаны через предоставленные Apple версии Markdown. Они объясняют существование двух путей, но не устанавливают, какой именно нативный клиент использован установленными Online и Infuse.

loopback=>1 согласуется с входом через локальный прокси; пакетный tcp stream согласуется с перехватом пакетов. Это интерпретация, а не доказанная привязка конкретных API к двум приложениям. Исходника установленной нативной Lampa MX, внутреннего сетевого кода Infuse и документированной расшифровки флага Shadowrocket здесь нет. Ядро Lampa только передаёт Online `lampa://video?player=tvosav&src=...`; само это не определяет последующий сетевой стек.

Документированного способа принудительно выбрать тот же вход для Infuse через параметры плагина или текущие правила конфигурации не найдено. Формат передачи можно сблизить; одинаковый сетевой вход средствами плагина и текущего конфигурационного файла не подтверждён.

Shadowrocket проверен только для чтения. Файл побайтово совпадает с 566c648: SHA-256 `61bf7053601daf235d2767aa1e40a3888e7a8bc59e57bbc8d6f5667ed56c993b`. Ограниченный статический парсер прошёл; сохранены Apple ALWAYS DIRECT и 17.0.0.0/8 выше внешних списков, три scoped DOMAIN-SUFFIX видеогруппы PROXY с их поддоменами, api.service-kp.com PROXY, FINAL,PROXY, подписки, General/Host и все остальные байты. Шесть удалённых Telegram IP-правил не возвращены. Полный cdntogo.net не направлен через PROXY. Результат: `audit/mx19-shadowrocket-readonly.json`. Это не проверка фактического правила после DNS/перенаправлений или эмуляция Shadowrocket.
