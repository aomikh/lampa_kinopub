# Диагностика Infuse и нативного аудио: mx.22

10.10.2026. База: `d660ee7df0eb58587a8594207681435e38b85261`, опубликованная `1.0.73-mx.21`. Ветка: `fix/infuse-device-native-audio-mx22`. Изменения требуют проверки на устройстве. ## Репозиторий и публикация

Публикуется `docs/` из main: последний успешный запуск [pages build and deployment №37740020954](https://github.com/aomikh/lampa_kinopub/actions/runs/37740020954) относится к этой базе. Публичный kp.js сверён с базой: 239061 байт, SHA-256 `18b9053e5b560329273944223abd0bd341e79c6e21190bb270ffd5e594e299ef`.

В mx.22 main и Pages не изменяются. Для публикации нужен подтверждённый пользователем конкретный коммит, затем обновление main, успешный Pages и сверка опубликованных байтов. Номер в query string сам по себе ничего не публикует.

## Что обнаружено и исправлено

1. mx.21 уже имела отдельный OAuth-профиль Infuse. Второй механизм не создавался. Не хватало сохранения device.id и проверки результата `/device/notify`: HTTP 200 с `status:400` считался успехом, а временная ошибка notify также могла отмечать устройство готовым. Теперь Infuse становится готовым после проверки одного и того же id и чтения назад точных title/hardware/software. Сетевая ошибка сохраняет токены, но не выдаётся за подтверждённое описание.
2. Уведомление каталога могло заменять пользовательское имя устройства. Теперь сохраняется название, полученное из `/device/info`. Защита от одинакового access token или уже известного одинакового id останавливает подготовку Infuse до изменения устройства каталога.
3. После отмены запроса ожидающий общий refresh мог запустить повторный запрос закрытого источника. Отмена теперь отслеживается отдельно от обновления токенов устройства. Общий refresh продолжает обслуживать других ожидающих клиентов.
4. Успешный GET, начатый со старым токеном и завершившийся после его ротации, мог отдать старую ссылку. Такой ответ теперь повторяется один раз с текущим токеном либо отклоняется. Это правило свежести клиента, а не доказательство недействительности всех CDN-ссылок после refresh.
5. Ошибка старого опроса кода получила такую же защиту от отмены и смены авторизации, как успешный ответ. Проверка описания объединяется в один запросный цикл на профиль; отменённый источник не продолжает запуск из позднего результата.
6. iPad с десктопным UA распознаётся по MacIntel и touch points. Для Apple TV указывается только установленная платформа, без выдуманного поколения устройства, tvOS build или версии установленного Infuse.
7. Для Online, Universal и Pro режим «Авто» использует поле `hls4`. Выбранный файл и формат проверяются до запуска: отсутствие этого источника не заменяется HLS2, другой версией файла или качеством. Явная существующая настройка формата сохраняется. URL главного манифеста передаётся целиком, без извлечения одиночного video/audio rendition.
8. Синтетические `voiceovers`/`translate` не передаются нативным режимам и Apple inner/lampa. В текущем ядре `voiceovers` подавлял меню реально обнаруженных дорожек браузерного backend. Сохранённая JS-озвучка не изображается как выбранный звук нативного плеера. Настройки озвучки сохраняются для прежних поддерживаемых путей.
9. Даже фильм передаётся нативной оболочке с playlist из одного элемента: именно playlist сериализуется адаптером, поэтому timeline и субтитры остаются в доступном оболочке payload. Исполнение этих полей самой оболочкой не подтверждено.

## Четыре уровня Infuse

| Уровень | Подтверждённое | Что не установлено |
|---|---|---|
| OAuth-устройство | Документированный код устройства, отдельные access/refresh/expiry, независимое обновление и выход | Реальная первая регистрация текущего аккаунта в этом запуске не выполнялась |
| Описание | title/hardware/software документированы; изменяются для профиля интеграции и читаются назад по тому же id | Название не меняет доказанно серверный тип клиента; назначение `is_browser` не равно идентификации приложения Infuse |
| Ссылка | API получает item и точный максимальный file с токеном профиля Infuse; resolver вызывается с `type=http` | В документации не задан TTL подписи или зависимость её действия от refresh/отзыва устройства |
| Запросы Infuse к CDN | Firecore принимает подписанный URL через encodeURIComponent один раз; подпись, `+`, `%`, `&`, порядок параметров сохраняются тестами | Реальные HTTP-коды после остановки, заголовки Range/Content-Range, маршрут, размер и поведение на 30+ мин не наблюдались |

Существующий `client_id` равен **xbmc**. Он и существующий секрет не изменены. Документация предлагает получать client credentials у поддержки; нового `lampa`/`infuse` id не придумываем. `/device/notify` принимает только три описательных поля. Настройки support4k/supportHevc/supportHdr объявляют доступные форматы, serverLocation определяет регион, streamingType формат, mixedPlaylist влияет на состав HLS4. Из этих документов нельзя вывести, что переименование изменяет классификацию клиента или продлевает подпись. Для такого вывода нужен ответ KinoPub либо серверный журнал конкретного запроса.

Имя интеграции: **Lampa MX / Infuse / Apple TV**, либо соответствующий iPhone/iPad. software: Lampa MX, версия kp.js, известная версия ядра, external Infuse. Поле is_browser, если оно пришло в info, сохраняется как диагностическое значение, а не меняется вымышленным параметром.

| Данные | Каталог | Интеграция Infuse |
|---|---|---|
| access | kp_token | kp_infuse_token_v1 |
| refresh | kp_refresh | kp_infuse_refresh_v1 |
| expiry | kp_token_expires_at_v1 | kp_infuse_token_expires_at_v1 |
| id | kp_device_id_v1 | kp_infuse_device_id_v1 |
| описание и время проверки | kp_device_info_v1 | kp_infuse_device_info_v1 |

Существующие mx.21 токены используются повторно; первое обновление описания не требует нового кода. Внутри одной JS-сессии проверка готовности не создаёт новое устройство на каждом фильме. После полного перезапуска снова выполняется проверка существующего устройства. Ротация не удаляет id, выход или новая авторизация удаляют только локальные сведения выбранного профиля. Отзыв refresh очищает токены только при явном invalid_grant/invalid_token; временная ошибка их не удаляет. Logout не вызывает удаление второго устройства на сервере.

Это авторизация интеграции Lampa. Документированный интерфейс Infuse не реализует вход KinoPub внутри самого Infuse и не даёт плагину менять URL идущего просмотра или добавлять Authorization в последующие запросы плеера.

## Причина остановок

Подтверждены перечисленные ошибки клиента, но связь этих ошибок с остановкой уже запущенного фильма не доказана. Обезличенный журнал предыдущего проблемного запуска показывает закрытие удалённых соединений приблизительно через 61 и 76 секунд от создания, без HTTP-кодов и расшифрованных заголовков. Это может быть сервер, промежуточный маршрут или транспортный разрыв. По этим данным нельзя объявить ни 403, ни истечение ссылки, ни отзыв устройства.

Свежая действующая ссылка и доступ к аккаунту/Apple TV не предоставлены. Видеосервер не опрашивался по старым подписанным адресам. Наблюдений 401/403/410/429/5xx после остановки нет. Проверки Range в этом запуске выполнены на локальном HTTP-сервере, не на реальном CDN. `HEAD` отдельно не является критерием работоспособности.

Infuse сохраняет прямой файл максимального разрешения. Нет HLS2-эксперимента, скрытого снижения качества, обязательного прокси, скачивания фильма, пингов или таймера продления. OAuth expiry не используется как TTL медиа-ссылки. После перехода в Infuse Lampa может быть приостановлена. Если понадобится переподписание во время просмотра, изменение заголовков Infuse или устранение отказа CDN, это граница интерфейса Infuse/сервера KinoPub.

В 53 исторических записях главных HLS4-манифестов репозитория есть EXT-X-MEDIA AUDIO и ссылки вариантов на соответствующие группы. Обезличенная копия полного примера из logs/172714.899.txt сохранена в tests/fixtures/kinopub-hls4-master.redacted.m3u8: 18 audio records, три группы по шесть дорожек, включая русские студии и английский оригинал. Это альтернативные дорожки HLS, не 18 встроенных потоков каждого MP4. Состав группы зависит от конкретного контента и варианта; `audios[]` API и имя поля hls4 не гарантируют одинаковые дорожки всех файлов. У актуального прямого файла список встроенных потоков не проверялся. Отдельная версия видео с другой озвучкой в доступном API не подтверждена.

`tools/inspect_hls.py` читает один свежий главный манифест, не запрашивает дочерние плейлисты и сегменты, ограничен 128 KiB + 1 байт и 15 секундами. Отчёт содержит группы, реальные NAME/LANGUAGE, разрешения, кодеки и наличие ссылок на аудио, без подписанных URL. Media playlist не выдаётся за подтверждение единственной встроенной дорожки. Результат исторического примера: mx22-hls4-master.json.

Подтверждённого интерфейса для установки audio track в нативной оболочке или команды её смены во время просмотра не найдено. Выдуманные поля audioTrack/trackId не добавлены. В документированном KinoPub resolver нет параметра выбора аудио. Поэтому принудительный выбор до запуска также не реализован: audio-only URI, video-only child, blob или data из WebView не являются подтверждённой заменой полного источника для этой оболочки. Новый сервер ради такого обхода не вводится. **Задача полноценного нативного переключения остаётся открытой** до проверки собственного меню оболочки либо получения её подтверждённого bridge. Доступный корректный путь этой ветки: полный серверный источник и меню самого плеера, если оно поддерживает эти дорожки.

Изменения не перезапускают видео при выборе звука и не меняют позицию/серии/субтитры командой смены дорожки. В payload сохранены исходные данные; их применение, фактическое разрешение HLS при адаптации и сохранение выбранного звука на следующей серии зависят от оболочки и проверяются на Apple TV. Наличие нескольких разрешений в master не означает фиксацию одного разрешения плагином.

## Состав и откат

Изменены docs/kp.js, тесты авторизации/Apple-адаптеров/runtime и документация установки/Pages/HANDOFF. Добавлены два JS-набора, HLS inspector, его Python-тесты, обезличенный master и результаты в audit. Серверы, зависимости, Shadowrocket, Safari-скрипт и другие репозитории не менялись.

Для проверки до main используй закреплённый CDN-адрес кода `498d58b` из INSTALL_LAMPA_MX.md, одна активная копия расширения. В текущем ядре plugins.js → Utils.putScriptAsync загружает script src. GitHub Raw проверен: text/plain и nosniff, поэтому такая тестовая инструкция была исправлена отдельным коммитом. jsDelivr для точного SHA проверен: HTTP 200, application/javascript, CORS *, SHA-256 `20b8a8990ecc54876748dfa98efe9b262be96d3158c7149114dee0ec7c236dd1`, 247791 байт, как у проверенного локального файла. Это доставка расширения, без изменения видеопути. Ветка включает код и последующее уточнение инструкции; реальная установка на Apple TV не проверена. Сведения о доставке: mx22-plugin-delivery.json.

После подтверждения публикации: Pages URL с `?v=1.0.73-mx.22`, полный перезапуск, проверка номера в существующей диагностике. Существующее устройство Infuse не отключай ради обновления описания.

Откат тестовой установки: заменить URL расширения на опубликованный mx.21 и полностью перезапустить Lampa. Откат после публикации: git revert двух коммитов ветки mx.22 в обратном порядке, затем обычный Pages deploy, без переписывания main. Для изолированной ветки также можно подготовить совокупный обратный коммит через `git revert --no-commit d660ee7..HEAD`, проверить diff и закоммитить его. Диапазон не использовать, если в main уже появились посторонние коммиты. Новые диагностические ключи старой версии не мешают; рабочие токены mx.21 совместимы. Временный возврат native к прежнему формату возможен через существующую настройку HLS2, но не считается решением переключения аудио.
