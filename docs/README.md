# Lampa kinopub plugin

Плагин-источник видео [kinopub](https://kino.pub) для медиацентра [Lampa](https://github.com/yumata/lampa). Ориентирован на Samsung Tizen (Tizen TV), работает также на webOS, Android и в браузере.

## Установка

Прямая ссылка плагина:

```
https://aomikh.github.io/lampa_kinopub/kp.js
```

В Lampa: Настройки → Расширения → Добавить плагин → вставить URL → Сохранить.

## Авторизация

При первом запуске плагин показывает Device Flow код kinopub — открыть [kino.pub/device](https://kino.pub/device) на телефоне или ПК, ввести код, и плагин автоматически продолжит работу.

## Настройки

`Настройки → KinoPub`:

| Поле                | Назначение |
|---------------------|------------|
| URL лог-сервера     | Адрес [log-server](./log-server/) для удалённых логов с ТВ |
| Макс. качество      | Верхняя граница потока |
| Формат потока       | http / hls / hls2 / hls4 / авто |
| CORS-прокси         | Опционально, на Tizen не нужен |
| Авторизоваться      | Открыть окно с кодом для kino.pub/device |
| Выйти из аккаунта   | Удалить токены |

## Лог-сервер

`log-server/` — мини Node.js сервер для приёма JSON-логов от плагина. См. [log-server/README.md](./log-server/README.md).

## Структура

```
.
├─ docs/        # содержимое GitHub Pages (kp.js, index.html)
│  └─ kp.js       # сам плагин
├─ log-server/    # мини HTTP сервер для удалённого логирования
└─ filmix.js      # рабочий пример другого источника (для сверки API Lampa)
```

## Лицензия

MIT (плагин). Плагин не аффилирован с kinopub. Используется публичный xbmc-клиент Device Flow OAuth, известный сообществу неофициальных клиентов.

## Текущая редакция 1.0.73-mx.10

**Результат Apple TV от 04.10.2026:** тестовый HLS2 в Infuse 8.5.6 (5763) завершился ошибкой «Сервер не сообщил размер файла». mx.10 на устройстве подтверждена, исправление воспроизведения не подтверждено. Для текущего просмотра оставить работающий VLC. Повторные HLS2-тесты без новых данных не рекомендуются. Код и номер версии после этого снимка не менялись.

Сообщённая пользователем версия Infuse: **8.5.6 (5763)**. Добавлен отдельный разовый пункт **Infuse: проверить HLS2** при долгом нажатии на строку фильма/серии внутри KinoPub. Он запрашивает HLS2 для точного файла через `type=hls2` или использует реальное `urls.hls2` из обновлённого ответа. Выбранное разрешение и позиция сохраняются; нет понижения качества, прокси Tizen, предзагрузки видео, повторных запусков или автоматической отметки просмотра. Тест передаёт только выбранный фильм/эпизод. Фактическую поддержку дорожек, субтитров, перемотки и скорости нужно проверить в Infuse.

Обычный Infuse остаётся на свежем прямом файле; формат остальных плееров не изменён. Базовая поддержка M3U8 в Infuse не доказывает поддержку конкретного HLS2 KinoPub. Это контролируемый тест альтернативной доставки, а не установленное исправление сетевой ошибки. **108/108 JS, 16/16 HTTP, 20/20 smoke** пройдены. [Инструкция и откат](https://github.com/aomikh/lampa_kinopub/blob/main/INSTALL_LAMPA_MX.md).

Единственная ветка ответвления — `main`, единственный опубликованный плагин — `docs/kp.js`. Старые файлы из `docs/releases` удалены; история изменений сохранена. Исходный проект: https://github.com/mainsync-afk/lampa_kinopub.

На Apple TV обычная кнопка **Смотреть** сразу открывает KinoPub для текущей карточки. Отдельная кнопка удалена; меню «Трейлеры / KinoPub» на обычное нажатие не появляется. Поведение сохраняется после возврата на карточку. Другие закрепления и интерфейс Tizen сохраняются. Обновление: https://aomikh.github.io/lampa_kinopub/kp.js?v=1.0.73-mx.10.

В mx.9 исправлена передача встроенным tvOS Pro / Universal / Online, системному выбору внешнего приложения, VLC, SenPlayer, VidHub и SVPlayer. Убран дополнительный GET медиассылки для журнала; выбранный URL больше не подменяется запомненным качеством ядра. Нет внутренних повторных запусков/переключений аудио и отметки «просмотрено» только из-за передачи ссылки. Сохранены штатные адаптеры, данные дорожек, субтитров, позиции и плейлиста. При «Авто» остаётся HLS2; явный формат и предел качества не изменяются. Максимум выбирается по доступным ссылкам для фактического плеера, а не старой подписи строки.

По сообщению пользователя Pro / Universal / Online уже запускаются быстро. Причина различия с Infuse и скорость новой редакции на устройстве не измерены. Настройки декодера/буфера нативной Lampa MX недоступны. Для текущего просмотра разумно оставить один из проверенных пользователем встроенных режимов. [Сравнение всех пунктов меню и границы интерфейсов](https://github.com/aomikh/lampa_kinopub/blob/main/audit/apple-players-review-20261004.md).

Исправлен воспроизводимый дефект: метка качества строки, подготовленная для другого плеера или только URL-вариантов, могла ограничить Infuse до 1080p при доступном прямом файле 2160p. Максимум теперь определяется по файлам для Infuse в пределах сохранённой настройки; явный выбор остаётся точным. Значение общего предела 1080 по-прежнему исключает 2160, автоматически настройки не меняются. Это исправление выбора, а не доказанное ускорение сети.

**Настройки → KinoPub → Диагностика Infuse** проверяет заголовки HEAD, начала, середины, открытого диапазона и конца текущего файла. До пяти запросов, до 30 секунд, без чтения тела. Результаты открываются отдельно; 200, неправильный диапазон, 416 и CORS не выдаются за успешную проверку. Проверка запускается только вручную. Отдельная CLI-утилита ограниченно проверяет тело, перенаправления и заданное смещение без вывода подписанных ссылок.

Ошибка Infuse о диапазоне/смещении 205444144 не устанавливает серверную причину. Снимок подтверждает загрузку mx.6 на устройстве: подготовка 387 мс, передача 1 мс; начальный диапазон 206, три запроса середины/конца не ответили за 6 секунд каждый из Lampa. Тело не читалось, запросы самого Infuse неизвестны. Получены журналы соединений Shadowrocket, но в них нет заголовков HTTP. Проба DIRECT дала ухудшение по сообщению пользователя и отменена отдельной задачей; её не следует повторять по старой инструкции. Свежая ссылка проблемного запуска недоступна. Устранение обрыва, ускорение и перемотка на Apple TV пока не подтверждены. Изменение кнопки «Смотреть» в mx.8 не является исправлением этой сетевой ошибки.

Для обычного запуска Infuse сохранена свежая прямая ссылка; нужные участки фильма после этого запрашивает сам Infuse. Документированный интерфейс запуска не позволяет плагину управлять Range или его буфером. Предзагрузка в Lampa не передаёт загруженные байты в Infuse. Автоматической смены ресурса нет. В режиме `Delivery: hls2-test` диагностика показывает сведения передачи и не посылает файловые Range-запросы к манифесту. Исправления mx.9 относятся к передаче остальным Apple-плеерам; тест mx.10 не объявляется исправлением зависания Infuse.
